2. MERMAID DIAGRAM CODE
===============================================================================

erDiagram
    ADMINS {
        uuid Id PK
        varchar Email UK
        text PasswordHash
        varchar FullName
        varchar Phone
        text AvatarUrl
        boolean IsActive
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    DEALERS ||--o{ PRODUCTS : "creates / owns"
    DEALERS ||--o{ ORDER_ITEMS : "fulfills"
    DEALERS {
        uuid Id PK
        varchar Email UK
        text PasswordHash
        varchar FullName
        varchar Phone
        text AvatarUrl
        varchar ShopName
        text ShopDescription
        varchar ShopCategory
        text Address
        text LogoUrl
        boolean IsApproved
        boolean IsActive
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    CUSTOMERS ||--|| CARTS : "owns"
    CUSTOMERS ||--o{ ORDERS : "places"
    CUSTOMERS {
        uuid Id PK
        varchar Email UK
        text PasswordHash
        varchar FullName
        varchar Phone
        text AvatarUrl
        text ShippingAddress
        boolean IsActive
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    CATEGORIES ||--o{ PRODUCTS : "classifies"
    CATEGORIES ||--o{ CATEGORIES : "parent of"
    CATEGORIES {
        uuid Id PK
        varchar Name UK
        text Description
        uuid ParentCategoryId FK
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    PRODUCTS ||--o{ PRODUCT_IMAGES : "has"
    PRODUCTS ||--o{ CART_ITEMS : "added in"
    PRODUCTS ||--o{ ORDER_ITEMS : "ordered in"
    PRODUCTS {
        uuid Id PK
        varchar Name
        text Description
        decimal Price
        int StockQuantity
        varchar Sku UK
        varchar ApprovalStatus
        text RejectionReason
        timestamptz PublishedAt
        uuid DealerId FK
        uuid CategoryId FK
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    PRODUCT_IMAGES {
        uuid Id PK
        uuid ProductId FK
        text ImageUrl
        int DisplayOrder
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    CARTS ||--o{ CART_ITEMS : "contains"
    CARTS {
        uuid Id PK
        uuid CustomerId FK
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    CART_ITEMS {
        uuid Id PK
        uuid CartId FK
        uuid ProductId FK
        int Quantity
        decimal PriceAtAdd
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    ORDERS ||--o{ ORDER_ITEMS : "comprises"
    ORDERS {
        uuid Id PK
        uuid CustomerId FK
        varchar Status
        decimal TotalAmount
        text ShippingAddress
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

    ORDER_ITEMS {
        uuid Id PK
        uuid OrderId FK
        uuid ProductId FK
        uuid DealerId FK
        int Quantity
        decimal UnitPriceAtPurchase
        decimal Subtotal
        timestamptz CreatedAt
        timestamptz UpdatedAt
    }

3. CARDINALITIES & CONSTRAINTS SUMMARY
===============================================================================

- Admins: Standalone security accounts.
- Dealers to Products: 1-to-Many (ON DELETE RESTRICT to protect product and order integrity).
- Categories to Products: 1-to-Many.
- Products to Product Images: 1-to-Many (ON DELETE CASCADE).
- Customers to Carts: 1-to-1 (UNIQUE CustomerId, ON DELETE CASCADE).
- Carts to Cart Items: 1-to-Many (ON DELETE CASCADE, Composite UNIQUE on CartId + ProductId).
- Customers to Orders: 1-to-Many.
- Orders to Order Items: 1-to-Many (ON DELETE CASCADE).
- Products to Order Items: 1-to-Many (ON DELETE RESTRICT - order history preserves bought items).
- Dealers to Order Items: 1-to-Many (Direct dealer linkage enables multi-vendor order routing & sales aggregation).
