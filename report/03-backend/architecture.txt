BACKEND CLEAN ARCHITECTURE SPECIFICATION
=========================================

Framework: ASP.NET Core Web API (.NET 9.0)
Architecture: Clean Architecture (4 Loose-Coupled Layers)
Solution File: backend/ECommerce.sln
Hosting Engine: Kestrel (Default Port: 5001)
ORM: Entity Framework Core 9.0 (Npgsql PostgreSQL Provider)
Cloud Database: Supabase PostgreSQL (AWS ap-south-1)

2. ARCHITECTURAL PATTERNS & PRINCIPLES
===============================================================================

1. Inversion of Control (IoC) & Dependency Injection:
   All services, repositories, and security handlers are registered in Program.cs as scoped or transient dependencies.
   Controllers depend solely on Application interfaces (e.g., IDealerService, IOrderService).

2. Repository & Unit of Work Patterns:
   - IRepository<T> provides standardized CRUD operations: GetByIdAsync, GetAllAsync, FindAsync, AddAsync, UpdateAsync, DeleteAsync.
   - IUnitOfWork coordinates atomic database transactions across multiple entity sets with SaveChangesAsync().

3. Data Encapsulation with DTOs:
   Domain entities never leak into HTTP API responses. Every input and output is strongly typed via Data Transfer Objects (DTOs) with AutoMapper projections.

4. Multi-Tenant Role Isolation:
   Admins, Dealers, and Customers are completely segregated at both the database level (3 dedicated tables) and the entity level, preventing identity collisions and privilege escalation.

5. Cross-Cutting Middleware:
   ExceptionHandlingMiddleware catches unhandled exceptions globally, mapping domain-specific errors (KeyNotFoundException, UnauthorizedAccessException, InvalidOperationException) to standardized JSON error payloads.
